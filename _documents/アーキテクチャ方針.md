# アーキテクチャ方針

## 目的

Pleasanter のカレンダー表示で休日を表示できるようにする。Google カレンダーのカレンダー ID と CSV から休日を取得し、CSS を生成して拡張スタイルとして配置する。

## 構成

```text
IHolidaySource  ─┐                     ┌─ FileStyleSink（ファイル配置）
 ├ GoogleCalendar ├→ Holiday[] → CssGenerator → StyleDefinition ─┤
 └ Csv            ┘                     └─ ApiStyleSink（Extensions API 登録）
```

- 取得元と配置先は interface で分け、CSS 生成は両方式で共通にする。
- 複数の取得元に同じ日付がある場合は後勝ち。CSV を最後に読むので、CSV で Google の名称や追加休日を上書きできる。
- CSS は日付順で決定的に出力する（差分が安定し、API 更新の要否も比較できる）。

## スタイルの分割と名前

CSS は「共通部」と「年ごと」に分け、名前に接頭辞を付ける（既定 `vvcsc_`）。

| 名前 | 内容 |
| --- | --- |
| `{prefix}core` | FullCalendar の曜日クラス（`.fc-day-sat`・`.fc-day-sun`）の色。日付を含まない |
| `{prefix}{yyyy}` | その年の祝日・祝日名（標準・FullCalendar）と、標準カレンダーの土日（日付ごと） |

- 年が変わっても共通部と過去の年は変わらず、差分が小さい。1 ファイル（拡張）あたりのサイズも抑えられる（標準カレンダーの土日を日付ごとに出すため、1 年で約 80KB）。
- 本体は、ファイルを名前順、拡張を `ExtensionName` 順に読む（`ExtensionInitializer`）。順序に頼らなくて済むように、共通部の除外（`.fc-day-other`）は `:where()` で詳細度を持たせず、年ごとの祝日の日付指定が詳細度で勝つ。標準カレンダーの土曜 → 日曜・祝日の優先は、同じ年のファイル内の記述順。
- 接頭辞で始まるものだけを管理対象とする。接頭辞は英数字・`_`・`-` の 32 文字まで（空は不可。`/prune` の範囲を決めるため）。

### 消えた分の扱い

各年のファイルは毎回その年の分を全部書き直すので、取得元から消えた休日は残らない。範囲（`/from`〜`/to`、既定は今年と来年）から外れた年のスタイルは、既定では残して警告を出し、`/prune` のときだけ削除する（接頭辞で始まるものに限る）。削除は書き込みが成功した後に行う。

## 配置方式

### ファイル配置（`generate`）

`App_Data/Parameters/ExtendedStyles/{prefix}core.css`・`{prefix}{yyyy}.css` を CSS 本文だけで書き出す。

実機（Pleasanter 1.5.8.1）で確認した制約: 本体（`Initializer.ExtendedStyles()`）がファイルから読むのは `ExtendedStyles/*.css` だけで、`*.json` は読まれない。`.css` は適用サイトなどの指定を持てず全ページに適用される。そのため `generate` で `/site-id` を指定するとエラーにし、サイトを限定する場合は API 登録（`ExtensionSettings.SiteIdList`）を使う。反映には本体の再起動が必要。

### API 登録（`register`）

`/api/extensions/get` で `ExtensionType: "Style"` を 1 回だけ一覧し、一式（共通部 + 年ごと）の名前と突き合わせる。なければ `/api/extensions/create`、あれば `/api/extensions/{id}/update`、本体と同じ内容なら更新しない。同名が複数あるときは止める。`/prune` のときは、接頭辞で始まり一式に含まれない拡張を `/api/extensions/{id}/delete` で削除する。送るのは `ApiKey`・`ExtensionType`・`ExtensionName`・`ExtensionSettings`（`Name`・`Description`・`SiteIdList`）・`Body`（CSS）。

本体 `ExtensionsController.cs` で確認した前提は、テナントの `AllowExtensionsApi`、`context.HasPrivilege`（テナント管理者など）、ユーザーの API キー。実機では `Security.json` の `PrivilegedUsers` も必要だった。

- **テナント**: 拡張は API キーの持ち主のテナント（`context.TenantId`）に作られる。本文に `TenantId` を入れるとそのテナントになる（`ExtensionModel.SetByApi`）ので、`/tenant-id` で指定できる。ただし `ExtensionInitializer` は全テナントの拡張（無効でないもの）を読み込み、`Parameters.ExtendedStyles` に入れるため、拡張スタイルはテナントに関係なく本体全体に効く。サイトの限定は `SiteIdList`。
- **http**: Pleasanter の API に https の制限はない。http も許可するが、API キーが平文で流れるため警告を出す。API キーは環境変数から読み、メッセージには出さない。

## パラメーター

固定の設定は Pleasanter 本体の `App_Data/Parameters` に倣う。このツールの `App_Data/Parameters` に、関心ごとに 3 ファイルへ分けて置く（配布物に既定値を同梱し、ビルド出力・発行出力へそのままコピーする）。

| ファイル | キー |
| --- | --- |
| `Holidays.json` | `GoogleCalendarIds`・`IcalUrls`・`CsvFiles`・`FromYear`・`ToYear` |
| `Style.json` | `Prefix`・`FirstDayOfWeek`・`Colors`（`HolidayBackground`・`SaturdayBackground`・`WeekdayBackground`・`HolidayText`・`SaturdayText`・`WeekdayText`） |
| `Placement.json` | `OutputPath`・`PleasanterPath`・`Url`・`TenantId`・`SiteIdList`・`Prune` |

- 本体と同じく、キーは PascalCase、既定値を null で書けば「未指定」、配列とオブジェクトで階層を持つ。同梱の既定値は組み込みの既定と一致する（単体チェックで確認）。
- 優先順位は コマンドライン > パラメーター > 既定値。`/parameters` でフォルダを変えられる（本体の `Env.ParametersPath` に相当）。相対パスはパラメーターのフォルダ基準。
- 未知のキーはエラー。資格情報は書けず、認証付き iCal は URL ごとに環境変数名（`BearerTokenEnv` / `BasicUserEnv` / `BasicPasswordEnv`）で参照する。名前を指定した URL は未設定をエラーにし、共通の既定の環境変数へ戻らない。
- 取得元は上書き方式。`GoogleCalendarIds` を省略（null）すると日本の祝日、空配列か `/calendar-id none` で Google を使わない。`/ical-url`・`/csv` は同じ項目だけを上書きし、他の取得元は残る。

## 日付ごとの種類（日祝・土・平日）と取得元の併用

日付ごとの色は 3 種類（`DayType`）。取得元（Google カレンダー・iCal・CSV）はすべて併用でき、`DayResolver` が日付ごとに 1 件へまとめる。

- 優先順位は **日祝 > 土 > 平日**。同じ日付に複数あるときは最も優先順位の高い種類だけを残し、低い種類は名称ごと捨てる（Google の祝日に CSV で `平日` を指定しても祝日のまま）。同じ種類の名称は、取得元の順（Google・iCal・CSV）に「 / 」でつなぎ、重複は 1 つにする。
- Google カレンダー・iCal は日祝。CSV は第 3 列で指定し（`日祝`（既定）・`土`・`平日`、英語名も可）、内閣府の CSV（2 列）はそのまま日祝になる。
- 日祝は日曜・祝日の色、土は土曜の色。平日は土日の色を打ち消す色（`WeekdayBackground` 既定 `transparent`、`WeekdayText` 既定 `inherit`）で、土曜の振替出勤日などに使う。日付ごとの指定は Core の土日（`:where()` で詳細度が低い）より詳細度が高く、土日の列にある日でも勝つ。
- 平日の打ち消しは、日のセル（標準カレンダーの月・週、FullCalendar の月・週・日の `td`）だけに付ける。FullCalendar の曜日見出し（`th`）は本体の既定が青地に白文字で、透明にすると読めなくなるため付けない。リスト表示は日付ごとに色を付けるため、平日は指定自体を出さず本体の既定のままにする。

## FullCalendar のリスト表示の土日

リスト表示の日付行（`tr.fc-list-day[data-date]`）には曜日クラスがないため、土日・祝日を日付ごとに年のファイルへ出す（`.fc-list-day-cushion` の背景、`.fc-list-day-text` と `.fc-list-day-side-text` の文字色）。実機（Pleasanter 1.5.8.1）で土曜・日曜・祝日の行に色が付くことを確認した。このため 1 年のファイルは約 44KB（祝日約 20 日と、リスト表示の土日約 104 日分）。

## 標準カレンダーの土日と `FirstDayOfWeek`

標準カレンダーは、セルに曜日クラスがない。以前は日付ごとに土日を指定していたため 1 年で約 80KB になったが、列の位置（`:nth-of-type`）で指定して共通部に移した。祝日だけが年ごとのファイルに残り、1 年のサイズは約 30KB に減った（FullCalendar は曜日クラスで、列の位置を使わない）。

- 週の開始曜日は Pleasanter 側の設定（`General.json` の `FirstDayOfWeek`、1.5.9.0 から変更可能）に依存するため、`Style.json` の `FirstDayOfWeek`（既定 1 = 月曜、本体の既定）で持つ。Saturday の列は `(6 - FirstDayOfWeek + 7) % 7 + 1`、Sunday は `(0 - FirstDayOfWeek + 7) % 7 + 1` 番目の `td`。
- 週の行にはグループ見出しの `th` が混ざることがあるため、`td` だけを数える `:nth-of-type` を使う。
- 本体側の週の開始曜日と合わせないと、土日の色が別の曜日に付く（実機で確認）。
- 構造の条件は `:where()` で詳細度を持たせず、年ごとの祝日の日付指定が読み込み順に依らず勝つ。
- 日付をまとめて指定する規則は `:is()` で 1 つにする（セレクターの前半の繰り返しを避ける）。

## 取得元

- Google カレンダーは公開 iCal（`https://calendar.google.com/calendar/ical/{ID}/public/basic.ics`）を使う。API キー・OAuth は不要で、公開カレンダーのみ対象。既定は日本の祝日カレンダー。複数 ID を指定できる。
- 任意の iCal URL（`/ical-url`）も取得できる。https のみ。認証は環境変数の Bearer または Basic（全 URL 共通）で、認証付きはリダイレクトを追従しない。URL は秘密の場合があるためメッセージに出さない。Google の公開カレンダーは同じ iCal 取得の URL 組み立てだけが違う。
- CSV は内閣府の `syukujitsu.csv` 形式（Shift_JIS・ヘッダー 1 行・`y/M/d`）をそのまま読む。UTF-8 も可。
- どちらも `/from`〜`/to`（既定: 今年と来年）の年で絞る。内閣府 CSV は 1955 年からあるため、絞らないと標準カレンダーの土日指定が膨らむ。

## CSS

標準カレンダーと FullCalendar の両方を 1 つの CSS で扱う。優先順位は記述順で、土曜 → 日曜・祝日の順（土曜の祝日は祝日の色）。前月・翌月のはみ出し日には色を付けない。

| | 標準カレンダー | FullCalendar |
| --- | --- | --- |
| 範囲 | `:is(#CalendarBody, [id^="CalendarBody"])` | `:is(#FullCalendar, [id^="FullCalendar"]).calendar-container` |
| 日付 | `td.container[data-id="yyyy/M/d"]`（0 埋めなし） | `[data-date="yyyy-MM-dd"]` |
| 土日 | 日付ごとに指定（曜日クラスなし・週の開始曜日が設定で変わるため） | `.fc-day-sat` / `.fc-day-sun` |
| 除外 | `:not(.other-month)` | `:not(.fc-day-other)` |
| 祝日名 | 月表示 `.day::after`、週表示 `td.is-weekly::before`（絶対配置） | `.fc-daygrid-day-top` / `.fc-col-header-cell-cushion` / `.fc-list-day-text` の `::after` |

標準カレンダーの年表示も `td.container` で `data-id` が月初日になるため、月表示は `:has(> div > .day)`、週表示は `.is-weekly` で限定する。

本体の既定スタイルは背景を `#CalendarBody td`・`#FullCalendar td` と ID セレクターで指定する（詳細度 1,0,1）。属性・クラスだけのセレクターでは負けるため、範囲を `:is(#ID, [id^=...])` にして ID 1 つ分の詳細度に揃え、`!important` は使わない（実機で、揃える前は FullCalendar の土日・祝日の背景が白のままだったことを確認）。

実機（Pleasanter 1.5.8.1）で確認した FullCalendar の DOM は、ルートが `div#FullCalendar.calendar-container.fc`、日セル `td.fc-day.fc-day-{mon..sun}.fc-daygrid-day[data-date]`（前月・翌月は `.fc-day-other` が付く）、見出し `th.fc-col-header-cell.fc-day-{...}`（週・日表示は `data-date` あり、月表示は曜日クラスのみ）、リスト `tr.fc-list-day[data-date]`。週・日表示の時間枠は `td.fc-timegrid-col[data-date]`。月表示の `.fc-daygrid-day-top` は日セル内の先頭要素で、週・日表示の終日行には付かない。FullCalendar の週の開始曜日は `FirstDayOfWeek` に従わず常に月曜始まり。週・日表示の見出しは本体の既定が白文字のため、祝日が平日でも見出しの文字色を指定する。標準カレンダーの週表示のセルには日付の数字（`.day`）がないため、祝日名はセルの右上に絶対配置した `::before` で重ねる（セルの流れに入れると、その日だけ予定が下がり、複数日にまたがる予定のバーがずれる）。週表示は表示中の 7 日がすべて見える日なので、月をまたぐ日（`.other-month`）にも色を付ける（月表示ははみ出し日に付けない）。
