# 開発ガイド

## 前提

.NET SDK 10（[global.json](../global.json)）、Node.js 24 以上（Markdown の検査）、PowerShell 7。

## ソース構成

| パス | 役割 |
| --- | --- |
| `src/CalendarStyleCreator/` | 本体（コンソール）。外部パッケージなし |
| `tests/CalendarStyleCreator.Tests/` | 単体チェック（コンソール。失敗で例外終了） |
| `examples/` | 入力例 |
| `_reference/Implem.Pleasanter` | 必要時に取得する参照専用ソース（Git 管理外・配布対象外） |

## ビルドとテスト

```powershell
dotnet restore --locked-mode
dotnet build -c Release --no-restore
pwsh -File scripts/test.ps1
npm ci --ignore-scripts
npm run lint:md
bash scripts/sync-agents.sh --check
bash scripts/test-sync-reference.sh
bash scripts/reference-isolation-check.sh
```

ビルド・CI に本体ソースは不要です。事実確認の前だけ `bash scripts/sync-reference.sh` を実行します。
worktree 間で共有するときは環境変数 `PLEASANTER_REFERENCE_DIR` に取得先を指定し、その場所を直接読みます。
取得結果と根拠の残し方は [参照ソース](../_reference/README.md) を参照してください。

配布 ZIP は `pwsh -File scripts/package.ps1` で `artifacts/package` に作ります。ZIP を App Service 相当の配置に展開して CLI を確認するスモークは `pwsh -File scripts/appservice-smoke.ps1` です（ネットワーク不要、CI は win-x86 / win-x64 / linux-x64）。

Docker イメージは `docker build -t calendarstyle .` で作れます（`docker run --rm calendarstyle help`）。

## コンソール出力

コンソール出力は英語固定です。Azure の開発者コンソール（Kudu）のエンコーディング制約で日本語が文字化けするためです。API キーと例外の詳細は出しません。

## 名義

著作権者・会社名・作者の名義は、次の表記に統一します（2026-10-22 決定）。

- 日本語: 株式会社ピー・エム・シー ITソリューション事業部
- 英語: PMC Co., Ltd. IT Solution Div.

`Directory.Build.props` の `Company`・`Authors` は英語名義、
`Copyright` は `Copyright (C)` に英語名義を続けた値にします。
`NOTICE` の自社著作権表示は年を維持し、英語名義を使います。
製品名・名前空間・リポジトリ名は名義とは区別し、変更しません。
第三者の著作権表示・ライセンス本文と、署名済みの同意記録は変更しません。

## ブランチ

`develop` が開発基準、`master` はリリース用です。作業は Issue から develop へ作業ブランチを切り、Draft PR（`WIP:`、`Closes #N`）で進めます。
