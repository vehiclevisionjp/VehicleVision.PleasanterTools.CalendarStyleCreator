# リリース手順

バージョンは vX.Y.Z。初期実装は 0.1.0 とし、正式なリリースはレビューと対象 Pleasanter 版での実機確認が済んでから作ります。

1. develop の CI、依存監査、CodeQL を確認する。
2. 生成した拡張スタイルを、ファイル配置と API 登録の両方で Pleasanter に配置し、カレンダー表示を確認する。未対応と既知の制約をリリースノートに記載する。
3. Directory.Build.props と package.json のバージョン、README を更新する。
4. develop から master への PR を作り、ユーザーが設定した保護ルールに従ってマージする。
5. master の確定コミットに vX.Y.Z タグを付ける。Release Actions が下書きを作り、OS・アーキテクチャ共通の ZIP と SHA256 を添付する。
6. 下書きのソース・内容・SHA256 と公開ライセンスを確認し、公開する。

ZIP は .NET 10 Runtime が必要なフレームワーク依存版。ソースは GitHub のタグから取得する。
必要時に取得する本体参照ソース・共有取得先・Git メタデータは配布 ZIP に含めない。

正式リリース用タグは検証前に作らない。レビュー用配布物は CI の artifact を使う。
