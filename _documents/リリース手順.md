# リリース手順

バージョンは vX.Y.Z。正式なリリースはレビューと対象 Pleasanter 版での実機確認が済んでから作ります。
アセンブリと配布 ZIP の版の単一情報源は `Directory.Build.props` の `VersionPrefix` です。
ルートの `package.json` の `version` は開発用ツールの版で、リリースの版とは連動しません。

## 一気通貫で出す（推奨）

「リリース実行（Release Run）」ワークフローが、版の引き上げ PR、`develop` → `master` の PR、
マージ、タグの push までを 1 回で通します。タグの push を受けて `release.yml` が**下書き**の Release を作ります。
**公開は人が行います**（下の「下書きの確認と公開」）。

1. `develop` の CI、依存監査、CodeQL が緑であることを確認する。
2. 生成した拡張スタイルを、ファイル配置と API 登録の両方で Pleasanter に配置し、カレンダー表示を確認する。
   未対応と既知の制約を、公開する Release の本文へ書く。
3. まず dry-run を実行する（既定が `dry_run=true`）。出る版と前提を確認する。

   ```bash
   gh workflow run release-run.yml --ref develop -f bump=patch
   ```

4. 問題なければ、実際に出す。`acknowledge` は、機械で確かめられない確認（破壊的変更の版、
   マイグレーション手順、依存のライセンス）を済ませた表明です。

   ```bash
   gh workflow run release-run.yml --ref develop -f bump=patch -f dry_run=false -f acknowledge=true
   ```

### 採番の決まり

- 起点は既存の最新 `v*` タグです（`scripts/release-next-version.sh`）。
- タグがまだ無い初回だけは、`VersionPrefix` をそのまま出す版にします（`bump` は無視）。
- プレリリース（`v1.0.0-rc.1`）は発行しません。必要になったら手でタグを付けます。
- **タグは付け直せません**（`release-tag-protection`）。間違えたら次のパッチ版を出します。

### 前提

`my-repo-automation-bot`（GitHub App）のトークンで動きます。`GITHUB_TOKEN` の push や PR 作成では
CI が起動せず、必須チェックが pending のままマージできないためです。

- Repository Variable: `MY_REPO_AUTOMATION_BOT_CLIENT_ID`
- Secret: `MY_REPO_AUTOMATION_BOT_PRIVATE_KEY`
- App の権限は Contents と Pull requests が Read and write

### 途中で落ちたとき

`develop` へのマージ後に落ちると、版だけ上がってタグが無い状態になります。
再実行すると、既にある PR とブランチは作り直さず引き継ぎます。
それでも進まないときは、落ちた段階を確かめて、下の「手で出すとき」の続きを手で行ってください。

## 手で出すとき

1. `Directory.Build.props` の `VersionPrefix` を上げる PR を `develop` へ出してマージする。
2. `develop` から `master` への PR を作り、保護ルールに従ってマージする。
3. `master` の確定コミットに `vX.Y.Z` タグを付けて push する。
   `release.yml` が、タグと `VersionPrefix` の一致を検査してから下書きを作る。

## 下書きの確認と公開

`release.yml` は、OS・アーキテクチャ共通の ZIP と SHA256 を下書きの Release へ添付します。

- 下書きのソース・内容・SHA256 と公開ライセンスを確認し、公開する。

ZIP は .NET 10 Runtime が必要なフレームワーク依存版です。ソースは GitHub のタグから取得します。
必要時に取得する本体参照ソース・共有取得先・Git メタデータは配布 ZIP に含めません。

正式リリース用タグは検証前に作らない。レビュー用配布物は CI の artifact を使う。
