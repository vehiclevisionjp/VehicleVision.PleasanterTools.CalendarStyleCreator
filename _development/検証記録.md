### 実機で見つかり、修正したこと（`CssGenerator.cs`）

1. 標準カレンダー・FullCalendar とも、本体の既定スタイルが `#CalendarBody td { background-color: transparent }`・`#FullCalendar td { background-color: var(--grid-cell-bg) }` と ID セレクターで背景を指定しており、修正前のセレクター（`[id^="…"]` とクラス）では詳細度で負けて土日・祝日の背景が付かなかった（FullCalendar で確認）。範囲を `:is(#CalendarBody, [id^="CalendarBody"])` と `:is(#FullCalendar, [id^="FullCalendar"]).calendar-container` に変更し、`!important` なしで勝つようにした。
2. 標準カレンダーの月表示で、祝日名を `.day::after` に足すと `.day` が 24px 幅の中央寄せのため日付の数字と重なった（`スポーツの日` が数字に被る）。名称のある祝日の `.day` に `width: auto; min-width: 24px; padding: 0 4px; justify-content: flex-start` を指定した。
3. FullCalendar の週・日表示で、平日の祝日（例 2026-10-12 月曜）の見出しは背景が祝日色になる一方、文字は本体の既定の白のままで読めなかった。祝日の見出し（`th.fc-col-header-cell[data-date]`）の文字色を指定した。
4. 検証用の色の期待値は既定テーマ（`CalendarTheme`）。テーマを変えた場合は未確認。

### 実機で見つかった要対応（本体側の仕様）

- ファイル配置は `ExtendedStyles/*.css` しか読まれない。`generate` が書く `ExtendedStyles/{Name}.json` を置いて本体を再起動しても CSS は配信されず（`/resources/styles` に出ない）、同じ内容の `.css` を置くと配信された。`FileStyleSink` の出力形式（`.json`）は見直しが必要。`.css` では `SiteIdList` などの指定ができず全ページ適用になる。サイト単位の限定が要るなら Extensions API 方式（`ExtensionSettings.SiteIdList`）になる。→ 対応済み: `generate` は `.css` で書き出し、`/site-id` はエラーにした（サイト限定は `register`）。
- 拡張スタイルのファイルも Extensions API で登録した拡張も、本体の起動時に読まれる（`ExtensionInitializer.Initialize` は起動時のウォームアップ）。配置・登録の後は本体の再起動が必要。
- Extensions API は、テナントの `AllowExtensionsApi`（テナント管理の画面で有効化）に加えて `Security.json` の `PrivilegedUsers` に API キーの持ち主のログイン ID が必要。API キーなしの呼び出しは 403 だった（認証できずテナントの許可を読めないため。`PrivilegedUsers` を欠いた場合の応答は未確認で、本体のコードでは 401）。
